# 判定流程

一条消息（或一次告示牌/铁砧/书编辑）进来后，按下面的顺序判定，**前面的命中就结束**。

```
聊天 / /me / 告示牌 / 铁砧改名 / 书与笔
   │
   ├─ 是否在管制范围？ 否 → 直接放行（老玩家 / 有 antiad.bypass 权限）
   │
   ├─① 地址规则（确定性、不花钱、不联网）
   │     IPv4 / 十进制数字 IP / 域名（后缀表 + 白名单）
   │     命中 → 影子隐藏 + 计数（可累计到封禁）
   │
   ├─② 敏感词 banned-words
   │     AI 开 → 连同命中的词作为线索交 AI 判
   │     AI 关 → 命中即影子隐藏（不计入封禁次数）
   │
   ├─③ 拼条检测 combine-messages
   │     最近 N-1 条 + 本条拼起来再跑 ①；只有"加上本条才拼得出来"的地址才算
   │     命中 → 影子隐藏 + 计数
   │
   ├─④ 结构异常 structure（软处理：只隐藏 + 扣分，不计入封禁次数）
   │     超长消息 / 数字过多 / 生僻字过多
   │
   └─⑤ AI 语义审核（可选）
         预筛命中才送；行为分类为"重点关注/广告号"则不看预筛全部送
         是广告 → 影子隐藏 + 计数；不是 → 原样放行
```

## ① 地址规则（最硬的一层）

广告要让人找到它，**必须留下可连接地址**，所以这一层不依赖词库也不依赖 AI。

- **IPv4**：`a.b.c.d`，每段 ≤255；局域网（`10.x`）、回环（`127.x`）、`172.16-31.x`、`169.254.x`、`100.64-127.x` 与带前导零的写法都不算。
- **十进制数字 IP**：`3107365173` → `185.54.161.53`；只认公网、8~10 位；形如日期（`20261012`）不算。可用 `settings.check-numeric-ip` 关闭。
- **域名**：后缀在内置 379 个"服务器常用后缀"里（两字母国别后缀 + 常见通用后缀，含 `ren`/`icu`/`wang`）。可用 `tlds` 覆盖。
- **白名单**：`whitelist.domains`（覆盖子域名）、`whitelist.ips`（逐字比对，也能放行你自己的 QQ 群号）、内置受信任平台表 `trusted-domains.txt`。

### 归一化（绕过写法处理）

在匹配前，文本会被统一化：

| 绕过写法 | 例子 | 归一化后 |
|---|---|---|
| 全角字符 | `ｍｃ．ｅｘａｍｐｌｅ．ｎｅｔ` | `mc.example.net` |
| 颜色代码插字 | `9.9.§c9.§r9` | `9.9.9.9` |
| 数字间空格 | `9 8 . 1 3 9 . 1 0 1 . 1` | `98.139.101.1` |
| 单字母间空格 | `m c . c o m` | `mc.com` |
| 汉字间空格 | `卖 号` | `卖号` |
| 各种"点" | `mc(dot)example(dot)net`、`mc 点 example 点 net`、`mc[.]example[.]net`、`mc·example·net` | `mc.example.net` |

## ② 敏感词

- AI 开启时**不作为独立处罚**：命中只把词作为线索（`{words}`）发给 AI，由 AI 结合上下文判断。这样"卖号角"这种包含词不会被直接隐藏。
- AI 未启用时退回旧行为：命中即只给发送者看（不计入封禁次数）。
- 只放**高精度**引流词；日常高频词放在 `ai.trigger-words` 里当"要不要问 AI"的开关。

## ③ 拼条检测

对付"把域名拆成多条发"：

```
玩家发：来看看这个 mc.example
玩家再发：.ren 挺好玩的 欢迎来玩        ← 第二条被拦，命中 mc.example.ren
```

实现要点：只有**加上本条才拼得出来**的地址才算命中（否则历史里的碎片会让后面每条消息连锁误判）。`structure.combine-messages: 1` 关闭。

## ④ 结构异常（软处理）

只看消息的"形状"，不做语义判断，因此零依赖、零联网：

| 检查 | 默认阈值 | 防什么 |
|---|---|---|
| 超长消息 | 120 可见字符 | 长文刷屏、藏链接 |
| 数字过多 | ≥8 位数字且占比 ≥50% | 手机号、身份证、QQ 号 |
| 生僻字过多 | CJK 扩展 A/B 区以上 >2 个 | 用生僻字规避词库审查 |

## ⑤ AI 语义审核（可选）

规则都没命中、且预筛命中（或该玩家属于重点关注/广告号）时，把消息与该玩家上下文交给配置的模型判断。细节见 [AI 审核](AI审核.md)。

## ⑥ 地址情报探测（SRV + 协议 + 网页标题）

规则命中地址、或消息要送 AI 时，会对消息里的地址做一次技术探测，回答"这个地址到底是不是一台 Minecraft 服务器"。结论**只当线索**，不直接决定封不封。

| 步骤 | 做什么 | 说明 |
|---|---|---|
| **SRV 判定** | 查 `_minecraft._tcp.<域名>` 的 SRV 记录 | 这个记录只有 MC 客户端会查，**存在基本就是 MC 服**；并且按记录指向的主机/端口去连（「域名 + SRV 指向别的端口」的服务器就不会被漏掉） |
| **协议探测** | 按 Minecraft 服务器列表协议（SLP）ping 一次 | 真服务器会回版本 / 在线人数 / MOTD；假网站、普通端口不会 |
| **网页标题** | 抓 `http(s)://<域名>/` 的 `<title>` | 只在**没确认**是服务器时才抓，看是不是「XX 我的世界服务器」这类站点 |

结果会：

- 作为 `{probe}` 线索进 AI 提示词（模型能据此判断"他拉我去的是一个真服务器还是个网站"）；
- 命中地址时，探测结论出来后再给管理员补一条通报（异步，不阻塞玩家）；
- **决定这次命中算不算封禁次数**（`probe.confirm-required`，默认开）：只要满足任一条就算确认 —— ① 有 `_minecraft._tcp` SRV 记录；② 25565 端口按 MC 协议回了服务器状态；③ **25565 端口连得上、只是不回状态**（对方开了 `enable-status=false` 或只挡了探测，这种服务器玩家照样能进，所以不能当成"假的"）。确认了 → 和以前一样累计到阈值就封 IP + 账号；三条都不满足（域名根本不存在、只是个网站、端口没人听）→ 只隐藏 + 通报 + 轻度扣分（1 分，不是广告命中的 3 分），**不计入封禁次数**。这条是为了防止"随手打一个不存在的网址"被累计封号。记录里会标成「只隐藏（没探测到服务器）」，既不算违规、也不影响老玩家判定。
- `/antiad test <文本>` 也会显示（方便你自己核对），最后一行的 `→ 会计入封禁次数 / → 只隐藏、不计入` 就是真实处置。

安全与开销：只探**公网地址**（回环 / 内网 / 链路本地 / CGNAT / 组播一律拒绝，免得被玩家当成内网扫描器）；所有网络请求都在异步线程；有总预算 `probe.timeout-ms`（默认 2 秒）与缓存 `probe.cache-seconds`（默认 10 分钟，同一地址不会反复探）；一条消息最多探两个地址。不需要可以直接 `probe.enabled: false`（那就会退回"规则命中即计入"的老行为）。

## 非聊天入口

| 入口 | 事件 | 命中后 |
|---|---|---|
| 告示牌 | `SignChangeEvent` | 取消（牌子保持原样） |
| 铁砧改名 | `PrepareAnvilEvent` | 清掉结果（拿不到改名物品） |
| 书与笔 | `PlayerEditBookEvent` | 取消（书内容不落盘） |
| `/me` 等广播命令 | `PlayerCommandPreprocessEvent` | 取消（只有 `settings.checked-commands` 里列的命令会检查） |

这三个入口**无法"只给本人看"**，所以直接拦下，并按地址命中累计（可导致封禁）。

## 命中后的动作

1. **影子隐藏**：`event.setCancelled(true)`（顺带让 TrChat 这类 `HIGHEST` 优先级的格式化插件跳过广播），再把内容只补发给发送者。
2. **通报**：写控制台 + 发给有 `antiad.notify` 的在线玩家。
3. **记录**：写 `hits` 表（时间/玩家/IP/类型/命中内容/整条原文/处理结果）。
4. **计分**：扣行为分（广告 -3、敏感词 -1），可能把该玩家降到"重点关注"。
5. **封禁**：累计到阈值（3 → 重点关注 2 → 广告号 1）→ 封 IP + 账号、踢出，理由带 `{contact}`。
