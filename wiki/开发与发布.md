# 开发与发布

## 构建

```bash
mvn package        # 产物：target/AntiAd-1.0.5.jar（shaded，约 130KB）
mvn test           # 61 个单元测试
```

- 需要 **JDK 21 或更新**（推荐 25）+ Maven；编译目标 Java 21（`maven.compiler.release=21`），这样一份 jar 能跑在 1.21.1 ~ 26.x。
- 依赖：`io.papermc.paper:paper-api:1.21.1`（provided，**故意对着最老的受支持版本编译**，只用到 1.21 就有的 API，所以新老服务端都能跑）、`bstats-bukkit`（shade 进 jar，重定位到 `cn.server.antiad.bstats`）、`sqlite-jdbc`（**只用于编译与单测，不打进 jar**：运行时由 `AntiAdLoader`（`plugin.yml` 的 `paper-plugin-loader`）在首次启动时从阿里云镜像下载到服务端 `libraries/`）。
- **构建注意**：不要把 `paper.api.version` 升到比 1.21.1 更高 —— 一旦用了新版本才有的 API，老服务端加载时会 `NoSuchMethodError`。确实要用新 API 的话，得先给老版本兜底（反射或按版本分支）。

## 代码结构（`cn.server.antiad`）

| 类 | 职责 |
|---|---|
| `AntiAdPlugin` | 生命周期、配置加载与自动补全、调度（区域化）、`record`/`notifyStaff`、线程助手 `runGlobal`/`runFor`/`runAsync` |
| `AntiAdLoader` | Paper 插件加载器：只负责把 SQLite 驱动从阿里云镜像（可被服务端配置覆盖）拉进类路径 |
| `Settings` | 读取 `config.yml` → 纯数据对象；内置资源（tlds/trusted-domains）加载 |
| `Detector` | **全部纯文本判定**：归一化、地址、敏感词、拼条、结构异常（无 Bukkit 依赖，易单测） |
| `Strikes` | 命中计数的滑动窗口 |
| `Behavior` | 行为分与分类的纯计算（含老玩家三条判定） |
| `BehaviorTracker` | 事件监听（进服/退出/挖方块/指令）、内存画像、缓存刷新、异步落库 |
| `ChatGuard` | 聊天/命令/告示牌/铁砧/书的入口与处置（影子隐藏、计数、封禁）、AI 扣留与放行、`combineHit` |
| `Ai` | OpenAI 兼容客户端（请求构造、JSON 解析、超时与 fail-open、token 用量） |
| `Store` | SQLite：`hits` / `usage` / `behavior` 三张表的读写（全部 `synchronized`） |
| `AntiAdCommand` | `/antiad` 子命令与 Tab 补全 |
| `Messages` | `&` 颜色代码 → Adventure 组件、占位符替换 |

设计约定：

- **纯逻辑放 `Detector` / `Behavior`**（无 Bukkit 依赖），这样都能单测；Bukkit 相关的胶水放 `ChatGuard` / `BehaviorTracker`。
- **线程规则**：聊天事件是异步的，处理器只读内存缓存；对玩家的动作一律 `runFor(player, …)`；数据库读写一律 `runAsync(…)`；玩家数据（统计）只在玩家自己的线程读。
- 不引新依赖；需要第三方时先问"标准库/已有组件能不能做"。

## 加一个新检测（示例流程）

1. 想清楚它属于哪一类：
   - **确定性地址类**（计入封禁次数）→ 在 `Detector` 里加纯函数 + 在 `ChatGuard.chat` 的地址分支附近接上。
   - **软类**（只隐藏 + 扣分，不计入封禁次数）→ 放进 `Detector.structureIssue` 那样的"结构"分支。
2. 在 `Settings` 里加配置项（含默认值）+ 在 `config.yml` 里加键和注释。
3. 写单测（`DetectorTest` / `BehaviorTest`）：命中用例 + **误伤用例**（这条更重要）。
4. 在沙箱服务器上做真机验证（下节）。同步 `README.md`、`FEATURES.md` 与本 wiki。
5. 若它会改变行为默认值，先在 wiki 的[常见问题](常见问题.md)里写清楚怎么关。

## 真机验证方法（沙箱）

无法用真人测试时，用假人 + 合成事件：

```java
// 1) 造一个真实在线玩家（用 fakeplayer 插件）
Bukkit.dispatchCommand(Bukkit.getConsoleSender(), "fp spawn");

// 2) 合成聊天事件（注意：Paper 要求异步触发）
Bukkit.getAsyncScheduler().runNow(plugin, task -> {
    AsyncChatEvent event = new AsyncChatEvent(true, player, viewers,
            ChatRenderer.defaultRenderer(), Component.text(text), Component.text(text), null);
    Bukkit.getPluginManager().callEvent(event);
    // 断言：event.isCancelled() —— 被拦 = true，放行 = false
});

// 3) 告示牌同理
new SignChangeEvent(block, player, new String[]{"来玩", "mc.example.com", "", ""});
Bukkit.getPluginManager().callEvent(event);
```

- **A/B 对照**最有效：把旧版 jar 和新版 jar 分别放进同一套插件环境，比较日志。
- 验证"影子隐藏"是否穿透聊天格式化插件时，另注册一个 `HIGHEST + ignoreCancelled = true` 的监听器模拟它：事件被取消它就不会收到 —— 能收到就说明漏了。

## 发布检查清单

- [ ] 版本号：`pom.xml` 的 `<version>`（`plugin.yml` 自动取 `${project.version}`）。
- [ ] **LICENSE** 文件（MIT / Apache-2.0 / GPL-3.0 之一）+ README 里一行说明。没有 LICENSE = 默认保留所有权利。
- [ ] README / FEATURES / wiki 与当前行为一致（尤其默认值与阈值）。
- [ ] `plugin.yml` 的 `author` / `description` 是你要对外显示的名字。
- [ ] jar 里**不含**任何服务器私有信息：确认 `config.yml` 的 `whitelist` 是占位符（`example.com` / `1.2.3.4`），`punish.contact` 是通用文案。
- [ ] 第三方依赖许可已声明：sqlite-jdbc（Apache-2.0，运行时由 `AntiAdLoader` 从阿里云镜像下载）、bStats（MIT，随包分发）。bStats 的插件 ID 正确（当前 `34706`）。
- [ ] 构建产物用 `target/AntiAd-<version>.jar`（shaded，约 110KB）；不要发 `original-*.jar`（没 shade，缺 bStats 重定位）。
- [ ] 敏感词/预筛词列表里若点名了具体服务器名，确认你有意为之。
- [ ] 发布后用真实服务器跑一遍：启动 → 进服 → 发一条广告 → 检查是否隐藏/封禁 → `/antiad records` 有记录。

## 用 git 发布的注意事项

```bash
git init
git add .
git commit -m "AntiAd 1.0.5"
```

`.gitignore` 已忽略 `target/`、`*.db`、`config.yml.bak-*`、IDE 文件。**不要**把自己的线上 `plugins/AntiAd/config.yml`（含自己的域名/IP/群号）提交进去。
