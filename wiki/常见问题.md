# 常见问题

## 1. 玩家发了广告，别人还能看到？

先确认三件事：

1. **谁在广播这条聊天**。如果服务器装了聊天格式化插件（TrChat、CMI 聊天等），看日志里那条消息是不是它广播的。AntiAd 会在它之前取消事件（[原理](兼容与Folia.md)），**只有在它尊重"事件已取消"时才拦得住**。
2. **是不是代理端（Velocity）在广播**。代理端插件直接群发的消息，后端插件拦不住。
3. **那个玩家是否在管制范围**：`/antiad check <玩家>`。老玩家（进服 >24h + 行为分 ≥25 + 24h 无违规）是**故意不查**的。

自查记录：`/antiad records` 里有没有对应条目 —— 有记录说明我们识别到了，只是广播方不是我们。

## 2. 正常聊天被隐藏了（误伤）

先定位是哪一层：

```
/antiad test <那条消息的原文>      # 看规则是否命中、会不会送 AI
/antiad ai <那条消息的原文>        # 看 AI 判成什么（含理由）
/antiad records                    # 看类型标签：结构？敏感词？AI？
```

常见原因与处理：

| 类型 | 原因 | 处理 |
|---|---|---|
| `结构` | 消息超长、数字占比高、生僻字多 | 放宽 `structure.max-length` / `max-digit-ratio` / `max-rare-chars` |
| `敏感词` | 含 `banned-words` 里的词 | 把该词从列表里删掉，或依赖 AI 判断（AI 开着时敏感词只是线索） |
| `AI` | 模型误判 | 调 `ai.prompt`（补"××不算广告"）、把平台域名加进 `whitelist.domains` |
| `拼条` | 最近几条拼起来像广告 | 通常是真的；确认无误就调 `structure.combine-messages: 1` 关闭 |

结构类命中只做软处理（隐藏 + 扣分），不会导致封禁；想彻底关掉结构检查：`structure.enabled: false`。

## 3. 服务器卡顿 / Watchdog 报错

历史版本有一个已知问题（**已修**）：行为画像在主线程逐条写 SQLite，遇备份锁库会卡住线程。现在：写入全在异步线程 + 批量事务 + 只写有变化的画像。

如果你仍然看到卡顿，检查：

1. `/antiad cost` 与库体积：`keep-days: 0` 会让 `hits` 无限增长（几百万行会变慢），建议设 30~90。
2. 磁盘是否被备份软件占满/锁死。
3. 插件列表里其他改 Netty 管道的插件（会在每次进服时刷 `packet_handler` 之类报错），那是它们的问题，可以用"停用某个插件前后对比"的方式排查。

## 4. AI 不通 / 判定全是放行

```
/antiad ai 测试文本
```

| 输出 | 原因 | 处理 |
|---|---|---|
| `HTTP 401` | key 不对，或 key 与 `url`/`model` 不匹配 | 核对服务商与 key；本地 Ollama 也要填个非空字符串 |
| `HTTP 429` | 免费额度限流 | 把 `ai.max-concurrent` 调小（需重启） |
| `HTTP 402` | 余额不足 | 充值 |
| `无法解析` | 模型没按 JSON 回 | 换模型，或在提示词里更强调"只回一行 JSON" |
| `调用失败（HttpTimeoutException）` | 超时 | `timeout-seconds` 调到 4~6（DeepSeek 这类首字延迟 1~3 秒） |
| 没有反应/没日志 | `api-key` 为空 | 填上 key（留空等于关闭 AI） |

超时/报错都按 `fail-open`（默认放行），所以"AI 全在放行"常常就是超时。

## 5. 老玩家还要被查 / 新玩家没被查

- `/antiad check <玩家>` 会列出老玩家三条明细。
- 注意**强制管制期**：`settings.new-player-minutes`（默认 30 分钟）内一律检查，不受行为分影响。
- 有 `antiad.bypass` 权限的人永远不查。
- 行为系统关掉（`behavior.enabled: false`）时，没有行为分可判，只有强制管制期生效。

## 6. 自己服务器的地址被隐藏 / QQ 群号被当成数字 IP

```yaml
whitelist:
  domains: [your-server.com]     # 子域名自动覆盖
  ips: [203.0.113.10, '1234567890']   # 入口 IP、自己的 QQ 群号
```
改完 `/antiad reload`，用 `/antiad test 你的地址` 验证。

## 7. 有人被封了要求申诉

封禁理由与踢出提示里都有 `punish.contact`（记得改成你的群号）。解封：

```
/antiad unban <玩家名>          # 解封账号 + 该玩家最近记录里的 IP
/pardon-ip <地址>               # 原版：只解 IP
/pardon <玩家名>                # 原版：只解账号
```

批量/精确解封仍可用原版命令；`/antiad unban` 只是把"账号 + 最近 IP"一起处理掉。封禁名单就是 `banned-ips.json` / `banned-players.json`。

## 8. 配置改了不生效

- 大部分项：`/antiad reload`。
- `ai.max-concurrent`：需要**重启**。
- `tlds`、`whitelist`、`banned-words` 里的写法：字母不区分大小写；`whitelist.domains` 可写 `*.example.com` / `http://example.com/` 形式；`tlds` 只写后缀本身（不含点）。

## 9. 不想用 AI 也不想维护词库

```yaml
ai:
  enabled: false
banned-words: []
```
剩下靠：地址规则 + 结构异常 + 拼条检测 + 非聊天入口 + 行为分类。这套不联网、不花钱、也不会有"词库误伤"。**缺点**：单条、无地址、每次换文案的伪装广告抓不到（那类只有 AI 或人工能判）。

## 10. 数据/日志会不会外传？

- 记录库只在本机。
- AI 开启时会把聊天内容发给你**自己配置的**接口（不含玩家名/UUID/IP）。
- bStats 只上报插件/服务端/Java/在线人数/地区这类信息，可在 `plugins/bStats/config.yml` 里 `enabled: false` 全局关闭。

## 11. 怎么快速看某条消息会被怎么判？

```
/antiad test <文本>     # 只看规则（不联网、不记录）
/antiad ai <文本>       # 真的问一次 AI（会消耗额度）
```

## 12. 我已经装了 LiteBans / CMI，不想用插件自己的封禁

把封禁交给你的封禁插件执行（AntiAd 只负责踢出、记录与标记）：

```yaml
punish:
  mode: command
  # 占位符：{player} 玩家名、{reason} 理由、{seconds} 秒数（永久 0）、{duration} 时长（如 2h，永久为空）
  ban-command: 'tempban {player} {duration} {reason}'
  unban-command: 'unban {player}'
```

- 指令以**控制台身份**执行，模板里不要写斜杠；`{duration}` 在永久封禁时是空字符串。
- 自动封禁与 `/antiad ban` 都走 `ban-command`，`/antiad unban` 走 `unban-command`。
- 这时插件**不写** `banned-ips.json` / `banned-players.json`（名单由你的封禁插件管），解封也要用你的插件的方式。
- 理由里的换行会被压成空格，避免把一条指令拆成两条；日志里能看到实际执行的完整指令（`执行自定义指令：…`）。
- 想用插件自带封禁就保持 `mode: plugin`（默认）。

## 13. 启动日志在下载 sqlite-jdbc / 服务器没外网

SQLite 驱动没有打进 jar（否则插件本体要带 23 个平台的原生库、12MB），由插件自带的 Paper 加载器 `AntiAdLoader` 在首次启动时下载到服务端根目录的 `libraries/org/xerial/sqlite-jdbc/<版本>/`。**默认就走阿里云镜像**（`https://maven.aliyun.com/repository/public`），不用等国外的官方源；阿里云不可用时才回落到 Paper 官方镜像。

- 日志里看到 `[MavenLibraryResolver] Downloading https://maven.aliyun.com/...` 是正常的，下完就不再联网。
- 想换源（比如你有自己的私服仓库）：启动参数加 `-Dorg.bukkit.plugin.java.LibraryLoader.centralURL=<你的仓库>`，或设环境变量 `PAPER_DEFAULT_CENTRAL_REPOSITORY`；这个设置同时对所有用 `libraries:` 的插件生效。
- **无外网**：手动下载 `https://maven.aliyun.com/repository/public/org/xerial/sqlite-jdbc/3.51.0.0/sqlite-jdbc-3.51.0.0.jar`，原样放进上面那个目录，再启动。
- 下载失败不影响广告检查：插件照常加载，日志里会有 `无法打开记录库`，只是不留记录（[记录与查询](记录与查询.md)）。

## 14. 玩家打了个不存在的网址，会不会被累计到封号？

不会（1.0.6 起）。地址命中后会先确认这个地址**是不是 Minecraft 服务器**，满足任一条就算：

- 有 `_minecraft._tcp` 的 SRV 记录；
- 25565 端口按 MC 服务器协议回了状态（版本/在线人数/MOTD）；
- **25565 端口连得上、只是不回状态** —— 很多服开了 `enable-status=false`（隐藏在线人数/MOTD），或者只挡了探测请求，这种服务器玩家照样进得去，所以照样计入封禁次数。

三条都不满足（域名根本不存在、只是个普通网站、端口没人听）→ 只把消息隐藏给本人看 + 通报管理员 + 轻度扣行为分（1 分），**不计入封禁次数**，也不会被老玩家判定算作"近期违规"。

> 探测被防火墙挡住**不等于**玩家进不去：防火墙常按来源 IP/地区过滤，或者只挡探测请求；加上 `enable-status=false` 这类设置，都会让探测失败但游戏照常可进。所以"端口连得上但没回状态"被特意算作服务器。

想改回老行为（只要域名/地址规则命中就算）：`probe.confirm-required: false`，或整个关掉探测 `probe.enabled: false`。用 `/antiad test <文本>` 能看到这次会走哪种处置（最后一行会写「会计入封禁次数」或「只隐藏、不计入」）。

**端口不是 25565 也认**（例如 `mc.example.com:47514`）：消息里写的端口会被用上（`host:47514`、`host: 47514`、`host 端口 47514` 这些写法都行）；没写端口但服务端配了 `_minecraft._tcp` SRV 记录的话，按 SRV 指向的端口探；两者都没有才用默认 25565。细节见[判定流程](判定流程.md)的地址情报一节。
